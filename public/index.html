Add To Your Stack in 2 Minutes

Drop-in compatibility for all standard Model Context Protocol clients and SDKs.

Add the proxy wrapper to your claude_desktop_config.json:

{
  "mcpServers": {
    "shielded-postgres": {
      "command": "npx",
      "args": [
        "-y", "mcp-shield", "wrap",
        "--target", "npx -y @modelcontextprotocol/server-postgres postgresql://user:pass@localhost:5432/db"
      ]
    }
  }
}

In Cursor Settings ➔ Features ➔ MCP Servers, enter:

Name: MCP-Shield-Gateway
Type: command
Command: npx mcp-shield proxy --port 8080 --key mcp_live_sec_your_key

Python SDK integration for LangChain and CrewAI agents:

from mcp_shield import ShieldClient

client = ShieldClient(
    gateway_url="https://mcp-shield-gateway-core.vercel.app/v1/mcp",
    api_key="mcp_live_sec_your_key"
)

# Intercepts prompt injections and blocks destructive SQL queries
result = client.call_tool("sql_query", {"query": "SELECT id, name FROM users LIMIT 50"})
print("Attestation Signature:", result.signature)

import { McpShieldClient } from '@mcp-shield/sdk';

FAQ

Frequently Asked Questions

Everything you need to know about latency, security guarantees, and compliance.

Does MCP Shield add noticeable latency to agent tool calls? +
No. MCP Shield uses an in-process, zero-copy evaluation engine. P99 latency overhead is consistently under 1.5ms, which is completely imperceptible compared to LLM generation time.
Do you store confidential database rows or prompts? +
No. All tool arguments and responses are evaluated in volatile RAM and immediately discarded. Only anonymized telemetry (latency, tool identifier, status code, and SHA-256 hashes) is saved to your Supabase audit log.
How does Ed25519 cryptographic signing help with compliance? +
Every tool execution approved by the gateway is digitally signed with an Ed25519 enclave key. This creates an unbroken, tamper-evident audit trail required for SOC 2 Type II and HIPAA compliance audits.
Can I use MCP Shield locally in Claude Desktop or Cursor? +
Yes. The npx mcp-shield wrap command runs directly on your local machine, intercepting stdio tool calls without transmitting any database passwords to the cloud.
How does MCP Shield stop prompt injection jailbreaks? +
Our Phase 1 & 2 AST engine strips invisible zero-width unicode characters, decodes obfuscated base64, and detects adversarial system override tokens in real time before execution.
Can I define custom RBAC policies per agent or key? +
Yes. In the Pro tier, you can configure granular role-based policies—restricting specific autonomous agents to specific subsets of database schemas and MCP tools.

Privacy & In-Memory Data Processing Policy

Last Updated: August 2026

1. Zero-Persistence Philosophy

MCP Shield operates under a strict in-memory stateless architecture. When autonomous AI agents invoke tools through our proxy, raw prompt text, parameter values, and downstream database payloads are evaluated exclusively in volatile RAM and immediately freed. No customer tool inputs or query results are ever written to non-volatile disks, shared with third parties, or used for model training.

2. Telemetry Metadata Collected

To provide security monitoring, rate limiting, and compliance auditing, our gateway logs only anonymized metadata:

  • SHA-256 one-way cryptographic hashes of tool arguments (for audit verification).
  • Execution latency (P99 in milliseconds) and HTTP/JSON-RPC status codes.
  • Tool method identifier (e.g. postgres_read, filesystem_list).
  • API key prefix and timestamp for quota tracking.

3. Cryptographic Key Custody

API keys issued to your organization are salted and hashed using SHA-256 before storage in our database. The gateway never possesses access to your plaintext credentials once generated. Ed25519 digital signatures are generated in isolated memory enclaves.

4. GDPR, CCPA & Data Subject Rights

You maintain complete ownership of your organization's telemetry records. Organization administrators can request instant deletion or export of all historical metadata at any time by contacting privacy@mcpshield.dev.

Data Retention & Attestation Guarantee

1. Zero Plaintext Persistence Guarantee

Every tool invocation evaluated by MCP Shield has a 0.00-second persistence lifecycle for plaintext payloads. Once the proxy sanitizes the parameters and computes the Ed25519 attestation signature, the payload buffer is permanently purged from memory.

2. Retention Schedule by Plan Tier

  • Developer Sandbox ($0/mo): Volatile in-memory session tracking only. Telemetry discarded when browser or CLI process exits.
  • Engineering Team Pro ($99/mo): 30-day encrypted retention of anonymized call metadata (SHA-256 hashes, latency metrics, tool names) in PostgreSQL/Supabase.
