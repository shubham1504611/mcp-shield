Without MCP Shield vs. With MCP Shield

Why running naked MCP connections exposes your organization to severe security vulnerabilities.

❌ WITHOUT MCP SHIELD

Direct Agent Connection

  • 🚨 Prompt Injections Pass Through: Adversarial web content or database rows can trick the agent into running unauthorized admin commands.
  • 🚨 Destructive DDL Mutations: Agent hallucinating DROP TABLE or deleting foreign keys permanently damages production schemas.
  • 🚨 Silent Data Exfiltration: Compromised agents can issue POST requests to arbitrary webhook URLs containing API secrets.
  • 🚨 Zero Cryptographic Auditability: No tamper-proof verification of whether an action was agent-generated or human-authorized.
🛡️ WITH MCP SHIELD

In-Memory Zero-Trust Proxy

  • ✓ Instant Unicode Sanitization: Phase 1 & 2 AST engine strips zero-width jailbreaks and neutralizes override tokens in under 1.5ms.
  • ✓ SQL Blast Radius Armor: Strictly permits parameterized reads, automatically rejecting destructive DROP, TRUNCATE, and mass deletes.
  • ✓ Strict Egress Whitelist: Restricts outbound tool connections exclusively to approved company domains and internal endpoints.
  • ✓ Ed25519 Cryptographic Attestations: Every valid frame receives an immutable digital signature for end-to-end cryptographic verification.

Add To Your Stack in 2 Minutes

Drop-in compatibility for all standard Model Context Protocol clients, reverse tunnels, and SDKs.

Add the proxy wrapper to your claude_desktop_config.json:

{
  "mcpServers": {
    "shielded-postgres": {
      "command": "mcp-shield",
      "args": [
        "wrap",
        "--target", "npx -y @modelcontextprotocol/server-postgres postgresql://user:pass@localhost:5432/db"

  }
}

In Cursor Settings ➔ Features ➔ MCP Servers, enter:

Name: MCP-Shield-Gateway
Type: command

FAQ

Frequently Asked Questions

Clear answers on architecture, privacy guarantees, zero-persistence RAM, and agent compatibility.

Does MCP Shield add noticeable latency to agent tool calls? +
No. MCP Shield uses an in-process, zero-copy evaluation engine. P99 latency overhead is consistently under 1.5ms, which is completely imperceptible compared to LLM generation time.
How does mcp-tunnel work without opening inbound ports? +
The mcp-shield tunnel command initiates an outbound-only connection from your private VPC/network to the gateway. When an AI agent invokes a tool, requests are securely routed down this established tunnel to your internal server.
How does Enterprise DLP protect sensitive PII and keys? +
Our Phase 2 engine checks tool arguments for Social Security Numbers (SSN), credit cards, RSA private keys, and API tokens. You can also configure custom regex patterns and block specific table names.
Do you store confidential database rows or prompts? +
No. All tool arguments and responses are evaluated in volatile RAM and immediately discarded. Only anonymized telemetry (latency, tool identifier, status code, and SHA-256 hashes) is saved to your audit log.
Can I use MCP Shield locally in Claude Desktop or Cursor? +
Yes. The mcp-shield wrap command runs directly on your local machine, intercepting stdio tool calls without transmitting any database passwords to the cloud.
What does mcp-shield doctor do? +
The mcp-shield doctor command scans your `.cursor/mcp.json` and `claude_desktop_config.json` files for unshielded servers, plaintext database passwords, and root filesystem privileges, offering 1-click auto-patching.

Privacy & In-Memory Data Processing Policy

Last Updated: August 2026

1. Zero-Persistence Philosophy

MCP Shield operates under a strict in-memory stateless architecture. When autonomous AI agents invoke tools through our proxy, raw prompt text, parameter values, and downstream database payloads are evaluated exclusively in volatile RAM and immediately freed. No customer tool inputs or query results are ever written to non-volatile disks, shared with third parties, or used for model training.

2. Telemetry Metadata & IP Rate Limiting

To provide security monitoring, DoS prevention, rate limiting, and compliance auditing, our gateway processes the following metadata:

  • SHA-256 one-way cryptographic hashes of tool arguments (for audit verification).
  • Execution latency (in milliseconds) and HTTP/JSON-RPC status codes.
  • Tool method identifier (e.g. postgres_read, filesystem_list).
  • Client IP address: Evaluated in memory strictly to calculate sliding-window rate limits (RPM) and returned in blocked threat response diagnostics for caller debugging; never persisted permanently to non-volatile disk.
  • API key prefix and timestamp for quota tracking.

3. Cryptographic Key Custody

API keys issued to your organization are salted and hashed using SHA-256 before storage in our database. The gateway never possesses access to your plaintext credentials once generated. Ed25519 digital signatures are generated in isolated memory enclaves.

4. GDPR, CCPA & Data Subject Rights

You maintain complete ownership of your organization's telemetry records. Organization administrators can request instant deletion or export of all historical metadata at any time via the official GitHub Security & Privacy Portal.

Terms of Service & Usage Agreement

Effective Date: August 2026

1. Permitted Service Utilization

MCP Shield grants you a revocable, non-exclusive license to route Model Context Protocol (MCP) JSON-RPC 2.0 traffic through our security proxy and WAF. You agree to utilize the gateway solely for lawful tool orchestration and security governance.

2. Fair Use & Prohibited Conduct

You may not intentionally exploit the gateway to launch Denial of Service (DoS) attacks, attempt to extract cryptographic private keys from our signing enclaves, or bypass rate limiting thresholds. Unauthorized reverse-engineering of AST sanitization filters is strictly prohibited.

3. Limitation of Liability

MCP Shield provides AST-level query validation and prompt injection defenses with high statistical efficacy. However, organizations are responsible for maintaining proper database permissions (such as read-only database roles) on their downstream systems.

Data Retention & Attestation Guarantee

1. Zero Plaintext Persistence Guarantee

Every tool invocation evaluated by MCP Shield has a 0.00-second persistence lifecycle for plaintext payloads. Once the proxy sanitizes the parameters and computes the Ed25519 attestation signature, the payload buffer is permanently purged from memory.

2. Retention Schedule by Deployment Model

  • Local CLI & Proxy ($0 Open Source): Volatile in-memory session tracking only. Telemetry discarded when process terminates.
  • Self-Hosted Gateway ($0 Open Source): Configurable storage backend via PostgreSQL or SQLite with custom retention policies.
  • Cloud Serverless Gateway: Zero-persistence in-memory ring buffer with live stream telemetry and Ed25519 signature headers.

3. Independent Cryptographic Verification

Every permitted response forwarded by the gateway includes an X-MCP-Signature header generated with our Ed25519 public enclave. Compliance auditors can verify transaction integrity mathematically without requiring access to confidential payload text.
