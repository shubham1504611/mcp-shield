# 📜 WAF Policy Versioning & Attestation Bump Protocol

## Overview
Every Ed25519 cryptographic attestation signature generated by MCP Shield binds to the active policy version:
```
<toolName>:<sanitizedPayload>:<nonce>:<timestamp>:<policyVersion>
```

This guarantees that compliance records and audit logs remain verifiable indefinitely, even as WAF rules and DLP patterns evolve over time.

---

## 1. Versioning Semantics

Policy versions follow Semantic Versioning (`MAJOR.MINOR.PATCH`):
- **PATCH** (e.g. `2.5.0` → `2.5.1`): New regular expression rules or DLP keyword patterns added without breaking existing signature formats.
- **MINOR** (e.g. `2.5.0` → `2.6.0`): New policy modes (e.g. `allowlist`), AST node validators, or optional tool parameter constraints.
- **MAJOR** (e.g. `2.5.0` → `3.0.0`): Changes to the canonical serialization tuple format, hash algorithms, or signature cipher.

---

## 2. Policy Bump Checklist

When releasing an update that modifies the canonical tuple structure:
1. Update `policyVersion` constant in `packages/gateway-core/src/security/waf.js`.
2. Update public JWKS key metadata `kid` in `api/_lib/handlers/jwks.js`.
3. Add backward-compatibility verification fixtures in `test/phase2-cryptographic-hardening.test.js`.
4. Run the full verification suite:
   ```bash
   npm run test:all
   ```
